RAG 不是万能药：短片段召回 0.42 到 0.82，长课却输给全上下文

同一套 RAG，在短片段上把答案命中率从 22.9% 拉到 58.0%，在 65 分钟长课上只有 25.5%，打不过全上下文。这是一次关于边界的复盘，附成本和三个我会改的决定。

RAGAgent多模态项目复盘
约 6 分钟

先看结论

  • 短片段：召回 0.416 → 0.824，答案命中 22.9% → 58.0%。
  • 长课（64.95 分钟）：检索 25.5%，全上下文 41.8%。
  • 成本约为全上下文的 1/25，但长课的效果是拿钱换的。

2025 年，我们 5 个人做智学多模态。目标很具体：把一节课的录像变成可检索的时间轴，复习时能跳回“第 12:30，第 8 页”。

我负责 API 和 Agent/RAG。

一年后回看，RAG 只在一种场景里赢得干净：短片段、要引用、要拒答。长课上，它输给了把整节课塞进上下文的模型。

下面按“结果 → 原因 → 怎么办”说。

结果：三种长度，三种答案

CEQA 是我们自己标的课程问答集，240 题，draft 版本。

测试集指标混合检索全上下文
短片段（7 段 / 27.6 分钟）ECR / 命中率0.833 / 48.5%—
全量 157 题ECR / 命中率0.824 / 58.0%61.8%
长课 64.95 分钟命中率25.5%41.8%

短片段上，检索明显有用。页面证据集中，命中就是命中。

全量上，我们追近了，但没超过。

长课上，差距最大：25.5% 对 41.8%。

原因：长课问的是“整节课讲了什么”

短课的问题，答案通常在一页 PPT、一段字幕里。检索把那一页找出来，模型就能答。

长课不一样。

学生问“这节课和上节课的模型有什么区别”，答案可能散在三四个章节里。检索每次只给回几个片段，模型看不到全局。

这不是检索的 bug，是它的工作方式。它只负责“找局部”，不负责“串起来”。

所以我没有把长课失败归因于 embedding 或 chunk size。换更大的模型、换更好的向量库，也补不上这个结构性缺口。

三个坑，都是顺序错了

先写 Prompt，后定编排。

最早想把流程塞进一个 Prompt。流程一长就散：答错了，不知道是检索错、工具错，还是生成错。

后来拆成意图路由 + 3–4 条子工作流，每一步单独看日志，才定位得到问题。顺序应该反过来。

先做功能，后建评测集。

没有固定题集时，每次改动都在新题上试，说不清是变好还是换题了。

补了 CEQA 之后，才敢说“这次有效”。前期慢，但比反复返工便宜。

先接工具，后收入口。

工具能“做事”，但没有统一入口时，鉴权、限流、审计要在每处重写，出问题也难复现。

后来补了 API Gateway，所有请求从那里进，才把线收住。

怎么选：一张简单的判断表

  • 用户要“定位、引用、拒答”：用检索。短片段、复习、客服知识库都合适。
  • 用户要“整节课/整份文档的全局理解”：先全上下文，或者先做分块摘要再检索。
  • 预算紧、问题局部：检索的性价比最高。
  • 预算够、问题全局：别硬上 RAG，效果会让你失望。

下一步

  • 把 pgvector 正式 RAG 补上（现在是混合检索 + 临时实现）。
  • CEQA 从 240 题扩到 400+，加跨学科留出。
  • 长课单独做“分块摘要 + 全局问题”的实验，不再拿一套管线打所有场景。

RAG 的收益有边界。承认边界，比多接一个模型有用。
