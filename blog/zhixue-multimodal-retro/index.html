RAG 不是万能药：一个课堂 Agent 的 0.42 到 0.82

短片段上，混合检索把召回从 0.42 拉到 0.82；长课上，它输给把整节课塞进上下文的模型。这是一次关于边界的复盘，附指标、成本和三个我会改的决定。

RAGAgent多模态项目复盘
约 5 分钟

先给结论。

短片段复习，混合检索把 ECR 从 0.416 拉到 0.824，答案命中率从 22.9% 到 58.0%。长课（64.95 分钟）上，同一套方法只有 25.5%，把整节课塞进上下文的模型是 41.8%。

我们没赢。但我知道它为什么没赢，也知道它适合用在哪。

问题：复习一节课，难在哪

一节课 45–90 分钟。学生真正想找的，往往是一句话、一个公式、一页 PPT。拖进度条找不到，重看一遍又太贵。

2025 年我们做智学多模态，5 个人，目标就一个：把课程录像变成可检索的时间轴。问答要能回到”第 12:30，第 8 页”。

我负责 API 和 Agent/RAG。

两种方案，先摆在一起

方案做法优点代价
全上下文整节课转写 + PPT 文本塞进模型理解完整，长课效果好token 贵，长视频会截断，难给精确引用
检索增强先检索片段，再让模型基于片段回答便宜、可引用、可拒答检索错了，后面全错；长课全局问题弱

我们选检索增强。不是因为它更强，是因为它更适合”复习”这个场景：用户要的是定位和引用，不是让模型写一篇课程总结。

实测：三种长度，三种结果

CEQA 是我们自己标的课程问答集，240 题，draft 版本。

测试集指标混合检索全上下文 B1
短片段（7 段 / 27.6 分钟）ECR / AnsAcc0.833 / 48.5%—
全量 157 题ECR / AnsAcc0.824 / 58.0%61.8%
长课 64.95 分钟AnsAcc25.5%41.8%

短片段上，检索明显有用：页面证据集中，命中就是命中。 全量上，我们追近了，但没超过。 长课上，差距最大。原因不复杂：问题需要跨章节的全局理解，而检索只给回局部片段。

成本这边，混合检索大约是长课全上下文的 1/25。省下来的钱，有一部分是拿效果换的。

三个我现在会改的决定

一、先定编排，再写 Prompt。

最早想把流程塞进一个 Prompt。流程一长就散：出错了，不知道是检索错、工具错，还是生成错。后来拆成意图路由 + 3–4 条子工作流，每步单独看日志，才定位得到问题。顺序反了。

二、先建评测集，再做功能。

没有固定题集时，每次改动都在新题上试，说不清是变好还是换题了。补了 CEQA 之后，才敢说”这次有效”。代价是前期慢，但比反复返工便宜。

三、入口先收口，再接工具。

工具能”做事”，但没有统一入口时，鉴权、限流、审计要在每处重写，出问题也难复现。后来补了 API Gateway，请求都从那里进，才把线收住。

我的判断

RAG 的收益有边界，边界由数据形态和问题类型决定。

  • 短片段、要引用、要拒答：检索划算。
  • 长课、要全局理解：全上下文仍然更好，或者先做分块摘要，再检索。
  • 对外只能说”能定位、能引用、便宜”，不能说”超过通用多模态大模型”。

下一步我会把 pgvector 正式补上，CEQA 扩到 400+，长课单独做”分块摘要 + 全局问题”的实验。不再拿一套管线打所有场景。
