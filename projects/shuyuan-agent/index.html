Project / 01

书院 Agent / RAG

把校园问答与办事流程拆成 3–4 条工作流，用 RAG 保证引用；评测集与知识库来自项目文档，规模未公开核验。

FastAPIRAGAgentPython

Metrics

  • 业务测试集 30+ 条
  • 知识库 4 类
  • 编排子流程 3–4 条
  • 交付形态 Web + 小程序

数据口径：简历与项目文档自述，未经第三方复现核验；服务规模未公开，故不列。

要解决的问题

把校园问答 / 办事流程做成可编排的 Agent，而不是一次性 Prompt。流程一长，单次 Prompt 就会把「哪一步出错」糊在一起。

架构（示意）

Input课程视频 / 字幕 / PPT
→
PipelineWhisperX 转写 · OCR · 页级对齐
→
Agent意图路由 → 3–4 条子流程 → RAG 引用

我做了什么

  • Prompt 工程与结构化对话流程：角色边界、拒答策略、安全机制。
  • Workflow 编排：意图路由 + 3–4 条子工作流，覆盖活动筹备 / 发布检查 / 当天运维 / 收尾复盘。
  • 知识库：推文 / 手册 / SOP / FAQ 四类 + 术语消歧表，强制召回保证一致性。
  • 评测：30+ 条业务测试集 + 契约测试接入 CI，验证版本变更后回答质量不退化。

测量计划

  • 固定评测集（问答复核），记录召回、延迟、token 成本。
  • 回归脚本接入 CI。
  • 目标：把 Top-k 召回、p95 延迟、单次成本补成可复现的公开基线。

状态

已上线校园场景；服务规模未公开核验，故本页不把它当指标。评测集与知识库数量来自项目文档，补齐召回/延迟/成本后会更新。
